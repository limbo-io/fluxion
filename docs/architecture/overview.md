# Fluxion 架构概述

## 系统定位

Fluxion 是一个分布式任务调度平台，采用 Broker-Worker 架构模式，支持高可用、可扩展的任务调度需求。

## 核心架构

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Console   │────▶│   Broker    │────▶│   Worker    │
│  (Vue Web)  │     │ (调度服务器) │     │ (执行节点)   │
└─────────────┘     └─────────────┘     └─────────────┘
                           │
                           ▼
                    ┌─────────────┐
                    │   MySQL     │
                    │ (持久化存储) │
                    └─────────────┘
```

## 核心组件

### 1. Broker (调度服务器)

Broker 是系统的核心调度节点，负责任务的管理、调度和分发。

**主要职责：**
- 接收 Worker 注册，维护 Worker 集群状态
- 根据调度策略触发任务执行
- 将任务分发给合适的 Worker 节点
- 管理任务状态流转和持久化

### 2. Worker (执行节点)

Worker 是任务的实际执行者，负责运行具体的业务逻辑。

**主要职责：**
- 向 Broker 注册并定期发送心跳
- 接收 Broker 分发的任务并执行
- 上报任务执行状态和结果
- 本地维护任务执行队列

### 3. Console (管理界面)

Console 提供可视化的任务管理接口。

**主要职责：**
- 任务配置管理（创建、更新、删除）
- 执行历史查看
- 实时监控和日志查看

### 4. DataSource (数据存储)

使用 MySQL 持久化存储任务配置、执行记录等数据。

## 通信方式

- **HTTP** (默认): 基于 RESTful API 的通信
- **Netty RPC** (可选): 基于 Netty 的高性能自定义协议

## 关键技术特性

| 特性 | 说明 |
|------|------|
| 分布式调度 | 支持多 Broker、多 Worker 集群部署 |
| 负载均衡 | 6种内置负载均衡策略 |
| 节点过滤 | 基于执行器、标签、容量的智能路由 |
| 任务类型 | 普通、广播、MapReduce 三种类型 |
| 调度类型 | FixedRate、FixedDelay、CRON |
| 高可用 | Worker 故障自动切换，任务重试机制 |
